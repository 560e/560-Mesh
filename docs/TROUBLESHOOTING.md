# 常见问题与排查

先确认当前目录与Compose项目：

~~~sh
docker compose ps -a
docker compose logs --tail=80 initialize
docker compose logs --tail=100 platform
~~~

发Issue前删除密码、Cookie、密钥、完整加入命令和真实设备信息。

## initialize退出

退出0正常，表示一次性初始化完成。退出1检查占位密码、账号格式、域名、目录权限与日志。
缺少560-mesh:local镜像时应先按部署文档构建；pull_policy为never，不会自动下载一个不存在的镜像。

## platform不健康

确认config/data挂载存在、目录所有者与容器65532用户匹配、基础配置可读、数据库可写。查看启动日志，不要盲目删除数据或禁用全部安全限制。
DNS或DERP保存后短暂重启属于受控应用。失败时检查界面的回退与错误状态；避免反复套用无效覆盖。

## 端口占用或映射不正确

端口写完整的127.0.0.1:宿主端口:容器端口。管理台映射3000，控制入口映射8080；两者不同，8081不外露。
占用应由你调整YAML或原服务，不会自动停止其他进程。宿主80/443由现有反代使用。

## 首页正常，管理台404或登录报错

管理台代理目录为/adminis/，目标URL保留/adminis。确认资源请求也到管理端口。
public_url、浏览器Origin、反代Host必须匹配；宝塔“发送域名”不要误填127.0.0.1。HTTPS Secure Cookie需要有效HTTPS。
查看平台日志中的脱敏诊断，避免通过关闭认证绕过问题。

## 能登录但加入失败

使用完整的设备加入命令，核对公开控制地址、密钥有效期/用户/是否可复用。服务器API Key不是设备认证密钥。
修改旧tailscale up偏好可能要求列出全部非默认参数；遵循客户端提示，或明确使用重置选项。
切换控制服务器可能需要强制重新认证。不要对不该重新登录的设备随意应用此选项。

## 显示设备在线但业务不通

检查用户隔离、ACL、路由批准、客户端系统防火墙和目标服务监听。在线只表示控制连接，不证明任意业务端口可达。
子网路由与出口节点还需要客户端转发能力。确认实际发布的CIDR和出口选择。

## DERP检测通过但依然中继失败

检测覆盖DNS、TLS与DERP握手。客户端到服务的网络、STUN/UDP和反代升级能力仍需独立验证。
使用Tailscale客户端诊断确认直连/DERP，不以控制台未采集的数据猜测链路。

## 修改YAML密码或DNS没有预期效果

初始化不会重置已有管理员密码。使用后台账号安全或匹配模板的管理员CLI。
magic_dns/base_domain在YAML只影响首次初始化；已有网页覆盖应在系统设置修改。

## 历史部署与新源码不同

保留已有标签、项目名、数据与端口，按升级文档操作。源码品牌更新不改变已导入的旧镜像。
README截图来自当前源码演示环境，不是对历史离线包界面的声明。
